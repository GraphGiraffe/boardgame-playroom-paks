# ХОД · игровые паки

Отдельный репозиторий готовых игр для [приложения и движка](https://github.com/GraphGiraffe/boardgame-playroom): **UNO, домино, дурак, шашки, змеи и лестницы**.

Текущая разработка — **0.4.0-preview.4**, API движка **1**, API представления **2**. Правила, варианты игры, бот, представление, стили, звуки и ресурсы принадлежат соответствующему паку. Исходники приложения здесь не дублируются. Соседняя игра про магов не включена.

## Установка

1. Скачайте `playroom.html` из релиза приложения и откройте в браузере.
2. Из [релиза паков](https://github.com/GraphGiraffe/boardgame-playroom-paks/releases) скачайте нужный `.playroom-pack.json`.
3. В приложении откройте **«Паки игр»**, выберите файл, просмотрите сведения и подтвердите установку.

Пак содержит исполняемый код: подтверждайте установку, если доверяете его автору. Интернет для дальнейшей игры не нужен. Архив коллекции содержит все пять установочных файлов; перед установкой их нужно извлечь.

Чтобы обновить игру, установите её новый файл. В текущем API 2 поддерживаются только новые паки. Старые опубликованные версии и сохранения не перезаписываются и не конвертируются автоматически. Версии приложения и игр не обязаны совпадать. Содержимое уже выпущенной версии не заменяется.

## Исходники

```text
packs/
  uno/
  domino/
  durak/
  checkers/
  snakes/
```

В каждом паке: `manifest.json` — основной источник метаданных; `rules.js`, `view.js`, `styles.css`; при необходимости `sounds.js`, `assets/`. `manifest.js` генерируется для совместимости модульных проверок и не является независимым источником настройки.

## Сборка и проверка

Python 3.9+, без внешних производственных зависимостей:

```sh
./build.sh
(cd dist && sha256sum -c SHA256SUMS)
```

В `dist/` появляются пять `.playroom-pack.json`, общий ZIP, архив исходников и контрольные суммы. `--output-dir` задаёт другую папку.

CI запускает те же `scripts/codex/setup.sh` и `check.sh`, проверяя синтаксис скриптов, сборку контейнеров и контрольные суммы. Полная проверка правил, мобильного интерфейса и обновлений выполняется вместе с приложением:

```sh
cd ../playroom
./build.sh --packs-dir ../playroom-paks/packs --prepare-dev --all-games
npm ci
npm test
```

Для другого расположения checkout укажите свой `--packs-dir`. Совместные тесты используют установленный Chrome/Chromium; путь задаётся `CHROME_BIN`.

## Codex Cloud

Для полной проверки выберите этот репозиторий и `boardgame-playroom` в одном окружении. Самостоятельно выполняются `bash scripts/codex/setup.sh` и `bash scripts/codex/check.sh`, без npm. При доступном приложении из корня паков используйте `bash scripts/codex/setup.sh --app-dir PATH` и `bash scripts/codex/check.sh --full --app-dir PATH`.

[Инструкция Cloud с готовым текстом настройки](docs/CODEX-CLOUD.md) разделяет сборку паков и совместную браузерную проверку. [AGENTS.md](AGENTS.md) описывает проектные правила; фактическая публикация Cloud-окружения выполняется отдельно.

## Следующий непубликованный вариант UNO 0.2.1 — жест обвинения

Ветвь разработки `UNO 0.2.1` добавляет заметные сообщения об объявлении UNO, пропуске и ошибочном обвинении и короткую кнопку `UNO!` над выбранной рукой соперника. Нажмите имя или руку игрока: платформа выделит обе области красной рамкой. Нажмите появившуюся кнопку `UNO!` либо выделенную область ещё раз за две секунды. Первый тап не выполняет действие, неверное обвинение штрафует обвиняющего на две карты. Инструкции находятся в меню правил UNO; алгоритм штрафов не изменён.

Общие таймер, визуальное выделение, уведомления, звук и результаты принадлежат приложению, а не игровому паку. Дополнительные поля `targetPrompt` и `event.notice` необязательны. `engineApi: 1` и `stateVersion: 1` остаются прежними. Опубликованную UNO 0.2.0 не перезаписывать; сохранённые партии требуют свою точную версию.

## Следующий блок: preview для телефона и ПК

В `feature/authority-responsive-preview`: UNO 0.2.0, дурак 0.1.1; коллекция 0.2.0-preview.1 ещё не опубликована. Приложение companion — одноимённая ветка boardgame-playroom, 0.14.0-preview.1. Две дополнительные поверхности пока только у UNO. Старые 0.1.0-партии требуют старый установленный пак; обновление не переписывает его.

Общий helper H.art задаёт каноническую геометрию. В mini-hand callback получает `{variant:'compact'}`; при отсутствии компактного рисунка используется основной. Интерактивные кнопки сохраняют собственную геометрию/доступность. UNO и дурак содержат оба рисунка, без новых ID компонентов.

Учебный пример: [examples/private-counter](examples/private-counter/README.md). `python3 build.py --include-examples` дополнительно собирает его JSON; обычный build сохраняет коллекцию из пяти игр. Пример не копирует код ядра в паки.

Для LAN-проверки из каталога приложения:

```sh
python3 dev/package-preview.py --packs-dir ../boardgame-playroom-paks/packs
cd dist/preview/playroom-preview
node dev/serve-preview.cjs --lan --players 4
```

Это тестовая партия в памяти Node, только доверенная сеть. Подробная инструкция находится в `boardgame-playroom/docs/PREVIEW-TESTING.md`; контракты — MULTIVIEW.md рядом с ней.

## API интерфейса 2

Все пять паков требуют приложение с viewApi 2 и возвращают элементы вместо готовой сцены. UNO 0.4.3; домино 0.3.3, дурак 0.3.4; шашки 0.3.1, змеи 0.3.2. Коллекция 0.4.0-preview.4 для приложения RC12. Старый интерфейс не поддерживается. Контракт: https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/GAME-ELEMENTS-API.md.

Обновлённые паки передают playerContent и содержимое рук основному приложению. Дурак передаёт отдельные группы stock/play. Все пять паков предоставляют поверхности table/player и поддерживают выбор первого игрока при создании. Компоновка, меню действий над игроком и обводка доступных объектов принадлежат приложению. Старые версии не поддерживаются этой итерацией.
