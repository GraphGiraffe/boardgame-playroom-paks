# Codex Cloud для игровых паков

Репозиторий содержит подготовку для облачной работы. Само Cloud-окружение здесь не создано: успешная локальная сборка или CI не являются подтверждением его публикации и запуска. Названия полей сверены с документацией 6 октября 2026 года.

Используйте `dev` с `scripts/codex/` после объединения PR подготовки. Для этого не требуется новый релиз в `main`; в прежнем опубликованном теге скриптов может ещё не быть.

## Два checkout для полной проверки

В текущем Cloud выберите **Work in → Cloud → Select environment → Create environment** и оба GitHub-репозитория. Проверьте подготовку, **Install script** и **Start skill**, затем **Publish**; после изменения зависимостей используйте **Republish**. [Официальное руководство](https://learn.chatgpt.com/docs/environments/cloud-environments).

Выберите `GraphGiraffe/boardgame-playroom-paks` и `GraphGiraffe/boardgame-playroom` через подключённый GitHub. Для обоих приватных репозиториев нужен доступ интеграции, а не PAT в скрипте. При исходной настройке предпочтительна `dev`, если доступна; рабочую ветку, уже созданную Cloud, не переключайте.

## Самостоятельная работа с паками

Из корня этого репозитория:

```sh
bash scripts/codex/setup.sh
bash scripts/codex/check.sh
```

Здесь нет npm-зависимостей. Python 3.9+ собирает контейнеры паков; Node.js 22+ используется для проверки JavaScript. Сборка и проверки структуры не заменяют выполнение игровых правил и браузерных сценариев.

## Совместная проверка

Назначьте `APP_CHECKOUT` реальному абсолютному пути корня репозитория приложения, затем выполните из checkout паков:

```sh
bash scripts/codex/setup.sh --app-dir "${APP_CHECKOUT:?Укажите путь к checkout приложения}"
bash scripts/codex/check.sh --full --app-dir "$APP_CHECKOUT"
```

`--app-dir` указывает на **корень приложения**. Для `check.sh` он используется только вместе с `--full`. Полный режим передаёт скриптам приложения текущий каталог `packs`; исходники не нужно копировать между репозиториями. Подготовка приложения использует закреплённый `npm ci`, выбирает Chrome/Chromium или устанавливает совместимый браузер Playwright. Системные библиотеки устанавливаются только по явному `--install-system-deps` вместе с `--app-dir`.

Путь браузера можно переопределить `CHROME_BIN`. Для предпросмотра из checkout приложения выполните `bash scripts/codex/serve.sh`, по умолчанию `127.0.0.1:4173`; аргумент задаёт другой порт. Приложение не требует сервера API, базы данных или токенов. Подробнее о его команде подготовки — [руководство приложения](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/CODEX-CLOUD.md).

## Сеть и обслуживание окружения

Начните с профиля **Package managers**, при необходимости добавьте конкретные домены загрузки браузера. [Настройки сети Cloud](https://learn.chatgpt.com/docs/environments/cloud-environments#connect-to-services).

В метаданных закреплённого `playwright-core` 1.63.0: `cdn.playwright.dev`, резервный адрес FFmpeg — `playwright.download.prss.microsoft.com`. После установки npm-зависимостей в приложении проверьте реальные адреса:

```sh
node node_modules/playwright-core/cli.js install --dry-run chromium
```

Дополнительные хосты перенаправлений разрешайте только по журналу конкретной неудачной загрузки. Для самой игры внешняя сеть не нужна. Если обновились зависимости приложения, подготовьте их и повторите совместную проверку перед новым снимком окружения.

В **Legacy** setup script и maintenance script относятся к отдельному режиму работы с кэшированным окружением. Не смешивайте их с текущими Install script / Start skill. [Документация Legacy](https://learn.chatgpt.com/docs/environments/cloud-environment).

Корневой [AGENTS.md](../AGENTS.md) содержит команды и границы проекта. Механизм вложенных инструкций описан в [официальном руководстве](https://learn.chatgpt.com/docs/agent-configuration/agents-md); личная конфигурация автора проекта не требуется.
