# Стихийная потасовка: брошюра правил

Принятая редакция 1: 16 страниц A5 и отдельная страница A5 с четырьмя одинаковыми памятками для вырезания, основной вариант с двумя ходами с разными типами действий, четырьмя картами, четырьмя здоровьями и двумя жизнями. Это первый этап патча 0.19.11. Редакция остаётся первой после согласованных правок. По отдельному поручению подготовлен цифровой вариант правил и общий механизм иллюстраций; его приёмка не заменяет приёмку PDF.

README описывает состояние редакции; фактическая механика берётся из domain. Прототип в соседнем репозитории не изменяется.

Арты компонентов извлекаются из `packs/mage-brawl/presentation/rule-illustrations.js`, обложка - принятая `assets/covers/arena-v8.webp`. Новые схемы используют те же тайлы и палитру. Чужие арты или тексты не заимствуются. Лицензирование игры и иллюстраций - [LICENSING](../../../packs/mage-brawl/LICENSING.md); общие условия документации - [корневой документ](../../../LICENSING.md).

- [King of Tokyo, IELLO](https://iellogames.com/wp-content/uploads/2021/10/KOT_Rules_EN_11-2023_Light.pdf), стр. 2: группы компонентов, изображения рядом с объяснением и визуальная иерархия.

## Физическое представление

Квадратная карта стихии разделена диагональю: движение и обычная атака. Тип задаётся отдельной многоразовой квадратной карточкой со следами, мечом или короной; каждому нужны три таких карточки. Это представление цифровой механики, а не новые игровые эффекты. В макете приведены показательные иллюстрации карт, а не готовый комплект для печати и вырезания.

Планы скрываются до общего раскрытия; направления обеих карт сохраняются. Указатель щита нужен отдельно, поскольку карта стихии уже в сбросе. В раскладке показана общая памятка с порядком фаз и схемами: в реализации **нет отдельной игровой колоды ультимейтов**, ультимейт выполняется картой стихии за корону. Макет не добавляет её правилом.

Состав арены и колоды вычислен по реализации: `sizeFor`, число баз = число игроков, каждой стихийной клетки `(size-2)/2`, каждого препятствия `size-2`, обычный пол заполняет остаток. Для базового лимита четыре карты каждой стихии нужно `players+1` экземпляров.

## Сборка

Нужны Python 3 (стандартная библиотека), Node.js 22+, локальный Chrome и `playwright-core` из соседнего PlayRoom. В GitHub Actions проверки и сборка брошюры не добавляются. Puppeteer/ReportLab не требуются.

```sh
python3 docs/design/mage-brawl-rulebook/build.py --out ../tmp_files/mage-brawl-rulebook/v1
node docs/design/mage-brawl-rulebook/render.cjs ../tmp_files/mage-brawl-rulebook/v1/rulebook.html ../tmp_files/mage-brawl-rulebook/v1/Стихийная-потасовка-правила.pdf
```

Команды допустимо запускать из корня коллекции; пути вывода при другом cwd указывайте явно. `PLAYROOM_APP_ROOT` переопределяет путь к приложению для поиска существующего браузерного адаптера. Пользовательский профиль браузера не используется. HTML автономный, без внешних шрифтов, сетевых ресурсов и библиотек; PDF содержит закладки по заголовкам.

Выходные файлы не включаются в runtime пака:

- `rulebook.html` - полный макет с встроенными SVG и обложкой;
- `Стихийная-потасовка-правила.pdf` - PDF из 16 страниц A5 без памяток;
- `Стихийная-потасовка-4-памятки-A5.pdf` - отдельный лист A5 с 4 памятками;
- `art/*.svg` - 37 векторных примеров для дальнейшей работы над иллюстрированной справкой;
- `source-record.json` - версии и SHA256 исходников, из которых извлечены иллюстрации.

`build.py` содержит редакционный текст и компоновку. `export-art.cjs` читает исходный renderer в изолированном VM с минимальными заглушками, не вызывает движок и не изменяет игровые файлы. Это локальный адаптер подготовки документа; он намеренно не является будущим API встраивания справки. Изменение точки извлечения в renderer требует обновить адаптер.

## Проверка макета

Проверены отсутствие переполнения страницы, 16 страниц A5 правил и отдельный PDF A5 с 4 памятками, выполнен рендер Poppler и визуальный просмотр всех страниц. После правки пересматриваются затронутые страницы. Проверяются разборчивость стрелок щита, самостоятельные направления шаров взрыва, целостность артов, нумерация, русские глифы и соответствие текста фактическим механикам. Изменений игровых правил, новой версии пака или публикации на этом этапе нет.

Общий контракт иллюстраций и краткие цифровые правила Стихийной потасовки подготовлены в предварительной версии. Следующий редакционный этап - остальные игры. Макет PDF сам по себе не закрывает их задачи.

Правки редакции 1: цветные рамки стихийных тайлов, жёлтая корона, общий меч с соосной рукояткой, компактные жетоны без буквенной фишки и подписи на раскладке, колода/сброс сверху, памятка/жетоны под ними, единый нижний ряд семи карт одинакового размера и шага. Метки 2 и 3 относятся к соответствующим группам. Терминология обновлена; в схеме столкновения показан урон Б и В.


## Печатные варианты редакции 1

После принятия раскладки подготовлены два самостоятельных файла. В раскладке поле увеличено; колода и сброс квадратные, того же размера, что тайлы и карты, колода показана стопкой. Справа сверху вниз: колода, сброс, памятка, жетоны. Метки 2, 3 и 7 находятся в верхнем левом углу групп; расстояние между группами карт больше внутренних промежутков.

`print-versions.py` сохраняет векторную графику и текст, переставляя 16 страниц PDF правил в спуск под скрепку: 16|1, 2|15, 14|3, 4|13, 12|5, 6|11, 10|7, 8|9. Получаются 8 сторон на 4 листах A4, альбомная ориентация. Печать: 100%, двусторонняя, переворот по короткому краю; режим буклета и дополнительное размещение страниц в драйвере отключены. Памяток в этом файле нет.

Отдельный односторонний A4 содержит два блока A5 с четырьмя памятками в каждом: всего восемь. Служебный footer отдельного листа A5 обрезан; пунктир и содержимое памяток сохранены. Страница альбомная, масштаб 100%.

```sh
python3 docs/design/mage-brawl-rulebook/print-versions.py ../tmp_files/mage-brawl-rulebook/v1/Стихийная-потасовка-правила.pdf --out ../tmp_files/mage-brawl-rulebook/v1
```

Дополнительная зависимость - `pypdf`. Скрипт создаёт два PDF, `PRINT.md` с настройками печати и `print-layout.json` с порядком страниц. Проверены 8 сторон буклета и 1 страница с 8 памятками, геометрия A4 landscape и визуальный рендер всех сторон. Физическая печать на пользовательском принтере не проверена. Правки сохраняются в редакции 1; публикации приложения этот этап не выполняет.

Согласованные визуальные решения перечислены в [ACCEPTED-DESIGN.md](ACCEPTED-DESIGN.md). Изменения переносятся в runtime и печатные иллюстрации через общие исходники; готовые SVG и PDF пересобираются, а не исправляются отдельно.

Зеркальная вёрстка разворотов (29 октября 2026): заголовок страницы и надзаголовок выровнены к внешнему краю — слева на чётных страницах, справа на нечётных. Номер страницы также стоит снаружи; строка нижнего колонтитула — с противоположной стороны. Основной текст и самостоятельный лист памяток сохраняют своё выравнивание. Спуск A4 использует эту же вёрстку A5; редакция остаётся первой.

Исключение для обложки: название «Стихийная потасовка» выровнено по центру. Надзаголовок и номер страницы сохраняют положение у внешнего края.

Памятки отделены от правил: `render.cjs` создаёт из общего HTML два PDF — 16 страниц правил и 1 лист A5 с 4 памятками (без сквозного номера 17). `print-versions.py` берёт отдельный лист A5 для раскладки 8 памяток на A4.
