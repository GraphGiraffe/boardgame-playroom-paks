# Правила для игрока

Полный текст принадлежит паку: `packs/<id>/locales/ru/game.json`, ключи `<id>.rules.N`; порядок задаёт `presentation/scene.js`. `manifest.json` содержит пояснения к переключаемым правилам. Краткие подсказки на поле и схемы карт — памятка, не замена полному тексту.

## Порядок изложения

1. Ситуация игры и понятная цель.
2. Состав поля, раздача, начальные условия. Объяснить термины до использования.
3. Что выбирает игрок и когда заканчивается его ход.
4. Порядок разрешения действий, особые карты, столкновения и исключения.
5. Добор, выход, восстановление, завершение и равные результаты.
6. После горизонтального разделителя — режимы и настраиваемые правила. Выбранные в текущей партии значения находятся в выделенных блоках рядом с пояснениями.

Один элемент массива `rules` — раздел: первая строка является заголовком, следующие строки — отдельными абзацами. Это обычный локализуемый текст, без HTML; renderer экранирует его. Старые однострочные правила показываются обычными абзацами. Количество ссылок в presentation должно совпадать с числом разделов. Локальное окно, комната и сетевой стол используют общий renderer приложения; тексты не копируются в приложение.

Не использовать необъяснённые сокращения, имена функций, слова «пакетный урон», «поезд», «прототип» или обещания будущей реализации как игровые правила. Для числа урона всегда указать получателя, источник, момент и способ защиты. Если эффект выглядит как усиление, но означает уязвимость, написать это прямо и дать пример. Настройки счёта объяснять числами, а не сравнением с другой программой.

При проверке сверять действия с `domain/` и общими зависимостями. Редактура текста не должна незаметно менять механику. Обнаруженное расхождение фиксировать отдельно; для расширения доступных вариантов требуется отдельная правка правил и проверка.

## Краткие иллюстрированные правила · подготовка 0.8.7

Внутри приложения текст должен помогать начать игру, не воспроизводить печатную брошюру целиком. Короткое лорное вступление, понятная цель, выбор игрока, порядок ходов и фаз, эффекты карт и тайлов, гибель/добор/победа. Иллюстрации показывают цифровое представление: текущую сторону карты и слайдер типа действия, без раскладки компонентов и физической рассадки.

Стихийная потасовка: раунд состоит из двух ходов, каждый ход - из восьми фаз (четыре движения, затем четыре атаки). Тип действия - движение, атака или ультимейт; это не синоним хода. При альтернативной настройке за раунд может планироваться один ход.

Presentation может объявить `metadata.rulebook.sections`: раздел с `text: MessageRef` (первая строка - заголовок), `figures:[{id,caption:MessageRef,role}]`, `layout:'grid'|'row'|'stack'|'list'` и необязательным `note:MessageRef`. Старый `metadata.rules` обязателен для текстового fallback. В локали остаётся текст, SVG и HTML туда не помещаются.

В `view.js` provider `illustrations: id => markup` передаётся в `V.register`. Он возвращает готовые публичные арты пака по семантическому ID; получает только ID рисунка, без состояния партии и доступа к authority. Схемы и рисунки не пересчитывают механику. Пример - `packs/mage-brawl`; общий renderer и сетевое прохождение описаны в [RULEBOOK-LAYOUT приложения](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/RULEBOOK-LAYOUT.md).

Стихийные карточки и тайлы показывают цветную окантовку и сохранённый фон; цвет схемы соответствует стихии. Корона всегда жёлтая. Общий меч принадлежит UI приложения и используется всеми паками; не добавлять отдельные копии в каждый пак. Печатный макет и цифровой renderer разделяют исходные арты, но не физические элементы управления.


## Принятый стиль · 28 октября 2026

Образец — цифровые правила Стихийной потасовки. Стиль распространяется на все 15 игр:

- Короткая цель, затем конкретные действия игрока. Один абзац — одна мысль.
- Количества писать цифрами: 1 карта, 2 кубика, 4 фазы. Не сокращать слова так, чтобы появлялись необъяснённые термины.
- Последовательность действий — нумерованный список; независимые условия — маркированный. Эффекты карт, варианты хода и сравнения — таблицы.
- Сохранять условия, исключения, точный момент эффекта и способы защиты. Не сокращать механику ради длины текста.
- Изображения ставить рядом с объясняемым действием: игровые элементы и интерфейс, с которым взаимодействует игрок. Использовать текущие компоненты и выбранный скин, а не обложки вместо примеров.
- Иллюстрации без лишних зазоров. Для тайла: картинка слева, описание справа; уязвимость и защита на отдельных строках. Порядок фаз подписывать над соответствующим рядом.
- Настройки и выбранные значения остаются в конце, после одного горизонтального разделителя.

`metadata.rulebook.sections[].blocks` поддерживает paragraph, list и table. Текстовые MessageRef переводит приложение; HTML в локаль не добавляется. `metadata.rules` сохраняет ту же информацию для старого текстового представления.

Примеры остальных игр находятся в `presentation/rule-illustrations.js`, подключаются через `sourceModules.view` и provider `illustrations`. Общий `PlayroomShared.rulebookArt()` отвечает только за компоновку публичных статичных примеров. Карты, кубики, шашки, фишки и кнопки берутся из игровых компонентов; специфичные лица карт передаются из view пака. Пример не получает Session, projection или действия партии. Все элементы находятся внутри `inert`, без команд и обучения. Иллюстрации не должны вызывать подсказки или отмечать освоенные действия.

Переработаны 14 остальных книг правил: объём основного текста сокращён примерно на 23%, добавлены списки и таблицы. Механика не менялась. Это локальные предварительные версии; стабильная публикация выполняется отдельно.

Змеи и лестницы: поправка ±1 прибавляется к исходному значению выбранного кубика, поэтому движение — от 0 до 7 клеток. Исходные грани остаются 1–6; дубль определяется ими. Результат 0 завершает перемещение без повторного запуска клетки, сохранённый щит не тратится. Автоматическое движение вторым кубиком использует его исходное значение.

## Краткий обзор для интерфейса 0.21

Каждый текущий пак дополнительно объявляет `metadata.rulebook.brief.sections` по тому же структурированному контракту. Три раздела — «Цель», «Ваш ход», «Финиш»; 60–100 слов с заголовками и подписями, для Стихийной потасовки до140. Достаточно основных действий для начала игры. Исключения и параметры остаются в полном документе, который редактура обзора не меняет. Локализованные ключи `<id>.brief.*` принадлежат паку; один или два рисунка повторно используют реальные существующие `rule-illustrations` без состояния партии и действий.
