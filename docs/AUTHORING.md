# Создание пака для ХОД 0.16

Коллекция 0.5.0-preview.2 допускает engineApi 1 и 2, viewApi 2, контейнер 1. Учебный [private-counter](../examples/private-counter/README.md) показывает полный минимальный исходник и приватную цель; это пример, не игра основной коллекции. UNO демонстрирует руки/реакции, шашки — поле и выбор цели, змеи — общий кубик.

## От примера до установки

Из корня этого репозитория при соседнем checkout приложения `../playroom`:

```sh
bash scripts/codex/setup.sh --app-dir ../playroom
python3 build.py --include-examples --output-dir dist/authoring
(cd dist/authoring && sha256sum -c SHA256SUMS)
```

Откройте приложение через `bash scripts/codex/serve.sh` из его каталога. В «Паки игр» установите `dist/authoring/private-counter-0.3.0.playroom-pack.json`, создайте партию и проверьте личный/публичный вид. Этот маршрут использует настоящее приложение; специальный Node preview host не обязателен.

Для своей игры скопируйте каталог examples/private-counter в packs/my-game. Согласованно замените id/name/version в manifest.json, регистрации правил и view, а также корневой CSS-класс. Задайте min/max, пресеты и правила вашей игры. Не меняйте уже опубликованный private-counter под прежним номером. Для своей новой версии используйте новый SemVer.

```sh
python3 build.py --output-dir dist/my-game
```

Сборщик включает каталоги packs, проверяет контракт и создаёт JSON каждой игры. Выберите `my-game-<version>.playroom-pack.json` в менеджере приложения. Не добавляйте игру в исходники ядра или index.html. При полном тесте стандартная коллекция из двенадцати игр должна оставаться доступной.

## Структура и версии

Обязательны manifest.json, rules.js, view.js, styles.css; необязательны sounds.js, assets/ и config/. manifest.js генерируется сборщиком. ID каталога, manifest и двух регистраций совпадают. Контейнер допускает до 128 файлов и 4 MiB; пути локальные без .., абсолютных путей и симлинков. Двоичные файлы включаются в JSON как data URL.

engineApi определяет контракт правил; viewApi=2 — контракт игровых элементов; stateVersion — схему состояния. Номер коллекции не заменяет version игры. Сохранение использует точную пару id/version; изменение правил/view/resources опубликованной игры требует новой версии. Автоматической миграции старого состояния нет.

## Правила и приватность

Регистрируйте один пак через TabletopCore.register. create заполняет state.data; legal перечисляет разрешённые действия; apply изменяет рабочую копию и задаёт следующий ход/исход. reactions разрешает внеочередные реакции, bot/botReaction выбирают из допустимого списка. validateState проверяет восстанавливаемые данные.

Используйте RNG ядра, сериализуемые данные и устойчивые ID компонентов. create учитывает options.resolvedFirstPlayer, если этот режим поддерживается. Не используйте DOM/Date/случайность окружения внутри игровой логики. События и sound-метаданные описывают результат, а не повторно меняют правила.

project(out, viewer, fullState) закрывает ваши нестандартные секреты до view/сети. У зрителя viewer=-1. Полное Session.export нельзя отправлять соперникам. Не раскрывайте руки в логах, HTML, доступных подписях, статусах или animation metadata. Проверьте не только экран, но и полученный JSON.

## Представление и ресурсы

PlayroomViews.register связывает ID с render(projectedState, viewer, actions, ui). Возвращайте api:2, family, playerContent и elements.field/hand/actions/status/auxiliary; дополнительные поля сверяйте с [действующим API](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/GAME-ELEMENTS-API.md).

Расположение игроков, toolbar, рук, счётчиков и общих объектов принадлежит приложению. View выбирает собственную графику и разрешённые действия. H.source/H.target связывают игровой объект с action; H.hand формирует общую руку; H.playerContent — разрешённое содержимое игроков. Не копируйте обработчики scroll/drag из движка. Неходовые карты должны оставаться доступными для прокрутки/осмотра.

Используйте H.esc для текста, H.actionAttr для действий, H.icon для общих значков. Счётчики points/wins/pieces передают публичные числа; pieces рисуется кругом, подпись сохраняется для доступности. Компактная графика не меняет данные и не раскрывает скрытую карту; для неё H.back.

CSS ограничивайте классом своей игры. Общие селекторы сцены/игроков/руки и внешние @import запрещены. PlayroomPack.asset('assets/file.svg') и локальный CSS url(...) разрешают включённые ресурсы. Не рассчитывайте на переписывание произвольных JS-строк с путями; используйте asset(). Файлы/лицензии ресурсов храните внутри пака. Для повторяемых карт, кубика, фишки и корабля используйте исходники `shared/`: укажите `sharedUi: true` и имена SVG в `sharedAssets`, например `card-back.svg` и `die.svg`. Сборщик встроит общий UI-код и эти ресурсы в каждый самостоятельный JSON.

В engineApi 2 вызов `TabletopCore.finish(state, [индексы победителей])` оформляет несколько победителей одной партии; `state.winners` передаётся вместе с обычным `state.winner`. Пример — командное Лудо и Дурак.

## Проверка и публикация

- Сборка и SHA256, JS-синтаксис; установка нового JSON и обработка отсутствующего/битого ресурса.
- Создание/полная партия/боты/Hotseat, легальные и нелегальные ходы, реакции, завершение.
- Сохранение/продолжение/replay без новой раздачи; точная версия и приватность каждого viewer.
- Портрет 320/390 px, короткий landscape, длинные руки, обе оси скролла, touch/drag/swipe и reduced motion. Публичный Стол без приватной руки/управления.
- Сетевой хост и клиент получают одинаковый подтверждённый результат, но разные разрешённые данные. Повтор команды не создаёт второй штраф/ход.

Запустите `bash scripts/codex/check.sh` и совместный `bash scripts/codex/check.sh --full --app-dir ../playroom`. Для новой игры добавляйте содержательные проверки правил/проекций в существующий набор приложения: общий прогон существующих игр не доказывает корректность нового пака.

Публикуйте новый versioned JSON с SHA256 и исходниками; содержимое старой версии неизменно. Документация правил: [PACKS](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/PACKS.md); [формат](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/PACK-FORMAT.md). Пак исполняется с доверием пользователя; sandbox, подписи, расширенный SDK и игровые часы — будущие работы.

## Приёмка интерфейса rc3

Перед копированием сверяйте два подходящих примера: UNO/Спроси рыбу для руки и выбора; Змеи/Лудо для доски и движения. Общая библиотека shared содержит каноническую карту 70×98 (5:7), квадратный кубик и обёртку обложки 300×180. Не переопределяйте ширину и высоту карты независимо: в Пексесо это приводило к почти квадратным картам.

- Рука — H.hand в elements.hand; действия — elements.actions с actionReserve; shared — только общий объект. Появление «Продолжить» не изменяет поле.
- Доска указывает fieldAspect; таблица/адаптивная сетка — fieldSizing: content. Клетки, кубик и круги остаются квадратными/круглыми при любом размере.
- Соперника выбирают его карточкой, карту — самой картой. Используйте targetKind/targetSource/targetChoice по контракту приложения, без матриц кнопок и закрытых ID.
- Счётчики не дублируют handCount. Текущие итоги вычисляют правила и передают в проекцию; view их только показывает.
- Объекты получают устойчивые публичные motion-маркеры; звук задаётся через extra.sound или документированный fallback. Не запускайте собственные таймеры, AudioContext или сетевые загрузки медиа.
- Скриншот без действий, с открытым onboarding или только начальный экран не является проверкой игры. Нужны состояния до/после действия, история, обе ориентации, открытая/закрытая рука и максимальный состав игроков. Проверяйте DOM-проекцию на отсутствие секретов.
- При изменении shared пересоберите каждый использующий пак и увеличьте его версию. SHA старых опубликованных JSON остаются прежними. Пример rc3: семь новых игр 0.1.1 и Дурак 0.4.1 используют sharedUi; Дурак получает обновлённую рубашку с пропорциями 5:7.

Файловый звук UNO хранится в assets/uno-call.wav и встраивается в sounds.js; эти байты должны совпадать. Остальные игровые сигналы используют общую синтезированную библиотеку приложения. Проверять звуки нужно с включённой настройкой после пользовательского жеста; загрузка/повтор snapshot не должны повторно проигрывать событие.
