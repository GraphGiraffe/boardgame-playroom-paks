# Автору пака · API 4 / UI 3

Перед изменением ресурсов и UI: [инварианты упаковки, скинов и проверки ошибок](DEVELOPMENT-REGRESSIONS.md). Исходники не являются составом готового пака.

## Слои

Сначала прочитайте [карту архитектуры и владельцев состояния](ARCHITECTURE.md). Для обучения — [контракт сценариев и пользовательского прогресса](https://github.com/GraphGiraffe/boardgame-playroom/blob/main/docs/TUTORIALS.md).

`packs/<id>/manifest.json` — метаданные/версии/режимы/доступные места/settings/capabilities/sourceModules. `domain/` — чистые правила. `presentation/` — SceneModel, ActionChoice labels и Event presentation после projection. `locales/ru/` — тексты. `rules.js` — только регистрация Definition в SDK. `view.js`/styles.css — Web renderer через общие компоненты; необязательные assets поставляются локально.

Эталоны: **tictactoe** (простое поле/полная модель), **yatzy** (публичные кубики/таблица/подтверждение), **gofish** (скрытая рука и публичные события), **private-counter** в examples (не входит в коллекцию).

```json
{"sourceModules":{"rules":["domain/game.js","presentation/scene.js"],"view":["presentation/scene.js","presentation/tutorial.js"],"locales":{"ru":["locales/ru/game.json"]}}}
```

GameModel Definition contractVersion=1: create/validate/actions/reduce/project/result/bot, дополнительные score/observe/reactions и decisionWindow при необходимости; GameModel.start — метод runtime, начальные события возвращаются из create. actions возвращают command + visibility; reduce возвращает position/events/turnEnded и при объявленном цикле roundEnded. Actor и viewer различать. RNG хранить в состоянии и передавать явно; бот видит разрешённую проекцию/память, не неизвестные карты.

Domain события — typed facts с visibility; presentation добавляет MessageRef, speech/notice/sound/feedback/reveal/sequence. Сначала privacy, потом перевод и Web. Полное состояние не передаётся гостю и не прячется CSS. Описание событий/метрик/прогресса — [SDK 0.18](https://github.com/GraphGiraffe/boardgame-playroom/blob/main/docs/SDK-0.18.md).

## UI

`PlayroomViews.register` принимает renderer элементов сцены. Общие Source/Target/Hand/BoardTarget/ScoreTable/Avatar/Reveal обслуживает приложение. Пак не рисует собственную шапку/toolbar/карточки игроков. Fixed scene default; один флаг allowLayoutChange может принадлежать только конкретному действию. Правила не зависят от DOM.

Рука прокручивается с любой карты, скрытые передачи рубашкой, публичные пары/сеты раскрываются общим reveal. Мини-руки обрезаны и перекрываются во всех рассадках. Доска с fieldSizing=fit сохраняет fieldAspect. Метрики/бейджи семантические, не распознаются по тексту. Скин меняет оформление после projection, не действие и не RNG.

## Сборка

```sh
python3 build.py --include-examples --output-dir dist/authoring
bash scripts/codex/check.sh
# in the companion app, with this exact checkout
python3 build.py --prepare-dev --all-games --packs-dir ../playroom-paks/packs
node scripts/codex/test.cjs case/pack-models,case/view-contract
```

Для новой игры добавить её в явный каталог/публикацию/проверки приложения и коллекции отдельным изменением; файл каталога не создаётся автоматически от появления папки. Найдите actual allowlists в build.py/scripts/publish-packs.py и loaders/smoke; не добавлять пустую игру. SourceModules собирает канонический shared/pack_compiler.py, manifest.js генерируется из JSON. Не редактировать generated manifest руками.

Новая логика требует соответствующих сценариев в существующем runner: варианты, deterministic seed, legal actions, privacy, result, restore/replay, bot, публичный Стол, mobile layout/gestures. Standalone syntax/build не заменяет эти проверки.

## Версии и выпуск

Неизменяемая packVersion при публикации; stateVersion меняется при форме данных, engineApi — при SDK. Поставки должны сохранять точные старые версии. Asset pack dependencies также точные. Коллекция 0.7.0 не заставляет менять правила каждой игры. Канонические shared-компоненты синхронизируются в host с digest, поэтому для их изменения нужна проверка обоих builder и общих потребителей.

[Процедура релиза](https://github.com/GraphGiraffe/boardgame-playroom-utils/blob/main/docs/project/app/RELEASING.md), [реестр механик](https://github.com/GraphGiraffe/boardgame-playroom/blob/main/docs/MECHANICS.md), [UI API](https://github.com/GraphGiraffe/boardgame-playroom/blob/main/docs/GAME-ELEMENTS-API.md).

## Метаданные редактора правил (0.18.1)

Необязательное `settings[].control` принимает `slider` или `select`; без указания сохраняется список. У слайдера позиции соответствуют порядку `options`, а сохранённые значения остаются `options[].value`, включая строковый `0` для отсутствия лимита. `label` и `help` задают подпись и справку. Колоды используют `select`.

`presetSetting: {label, help, control, options: [{value, label}]}` переименовывает и упорядочивает выбор preset в редакторе, не меняя domain IDs или значения по умолчанию. `ruleGroups: [{label, fields: ["preset", "deck"]}]` задаёт смысловые блоки по две ячейки в строке; `fields` ссылается на preset или settings key. Флаг `end: true` переносит блок завершения в конец после общих параметров. Каждый параметр перечислять один раз. Отсутствующие в группах поля сохраняются в редакторе, единственный вариант скрывается. `visibleWhen` проверяется по точным значениям правил, а не индексам слайдеров. Это метаданные Web UI, без изменения engineApi/viewApi/stateVersion.

В новых играх Рыбы/Акулины колода 54 не предлагается. Акулина показывает число карт в партии — 35/51, сохраняя внутренние deck IDs 36/52. Domain сохраняет чтение старых состояний с 54 картами; точные прежние опубликованные паки не переписываются.

## Скины компонентов

`skinFamilies: ["card-face", "card-back"]` перечисляет применимые типы, `defaultSkins: {"card-face":"mini-split"}` задаёт исходный вид. Индивидуальный выбор пользователя и явно выбранный Основной имеют приоритет. Настройки хранятся локально в приложении; пак не создаёт своё хранилище и не добавляет скин в правила/сохранение. Renderer использует общий asset resolver с контекстом пака. Типизированные метаданные проверяются compiler/runtime; новая metadata опубликованного пака требует новой packVersion.

Новые исходные паки `spider` и `klondike` используют общий чистый `shared/domain/solitaire.js` и `solitaire-board` без очередности ходов. Подсказки вычисляются из разрешённых публичных действий, не из запаса/истории authority.


### Читаемые зоны карточного скина

`shared/assets/catalog.json` → `card-face.stacking[variant]` хранит `protectedZones` (x/y/width/height в долях лица), минимальную открытую долю `horizontal`, `vertical`, `arc`, шаг рубашек `faceDown` и направление `wasteAxis`. Цветовые варианты используют одинаковую геометрию. Эти данные принадлежат ассетам, не правилам игры. Большой центральный знак требует большего открытого участка, чем компактный угловой индекс.

`helpers.assetLayout('card-face')` возвращает параметры активного скина для текущего пака. SVG лица также несёт `data-card-stacking`: общий fitter руки/веера и горизонтальных стопок использует минимум открытой доли; при нехватке места сохраняется прокрутка. Пасьянсы получают из тех же метаданных вертикальный шаг и направление сброса. Поле игры определяет раскладку, ассет — ограничения перекрытия. Переключение скина не меняет состояние партии.


Карточные сцены (`family:'cards'`) получают цвет поля от приложения: светло-зелёный/тёмно-зелёный по текущей теме. `PlayroomShared.cardSlot({label,suit,kind,attrs,className})` отображает пустое место карты, при заданной масти используя активный скин; `kind` описывает существующую игровую зону, не создаёт действие. Для локальной ошибки предусмотрен `data-feedback-required="<selector>"`: Input подсвечивает выбранные элементы внутри текущей сцены и не отправляет игровую команду. Предикат запрета и selector задаёт renderer из доступных действий и публичного состояния.


Колода персонажей: `character-face` — отдельное семейство от `card-face`. Сцена Пексесо выбирает актуальное семейство по типу колоды; демонстрационный объект для всех трёх вариантов — `circle-red`. Общие наборы персонажей сохраняют ID фигур/цветов и не влияют на пары или правила. Наборы аватаров используются приложением отдельно от предпочтений скинов пака.

### Подготовленная сборка и исходники

Компилятор оставляет потреблённые domain/presentation/locales модули только внутри правил и представления, не рядом вторыми файлами. scripts/styles общего набора также входят в view.js/styles.css один раз. Исходники остаются в репозитории и source ZIP. Авторские .md/.txt из assets не входят в runtime. Аудио хранится в assets/ один раз: sounds.js задаёт метаданные и получает src через PlayroomPack.asset, без второй base64-копии. Подробные персонажи characters — архивный набор; рабочие стили minimal («Стандартный») и simple («Простой»).

## Стандартные размеры

Основные карты, кубики, костяшки и фишки используют роли `--size-card`, `--size-die`, `--size-domino`, `--size-token`; миниатюры — отдельную роль. Не увеличивайте основную карту через ширину контейнера. Стили используют стандартные `--size-space-*`, `--size-type-*`, `--size-radius-*`, `--size-length-*` с fallback для автономного пака. Канонический каталог хоста — `core/size-tokens.json`, описание — app `docs/SIZE-SYSTEM.md`. При одинаковом viewport/ступени основной размер карты не зависит от game ID. Клетки доски и внутренние SVG-координаты производны от стандартного artboard; нестандартные базовые размеры требуют объяснения.

### Размерные роли, поведение и будущие зоны

Хост предоставляет `--size-*` и `--ui-duration-*`; автономные CSS fallback обязательны. Коэффициенты `stacking` и `protectedZones` остаются в манифесте скина: горизонтальное/вертикальное раскрытие, дуга, faceDown и ось сброса не заменяются произвольным паковым масштабом. UI-обводки в экранных px и SVG rim в viewBox имеют разные единицы.

Существующие `family`, `layout.focus`, `surface`, `actionReserve`, `playerContent.counters/badges/indicators` задают состав зон; общая раскладка не должна знать ID игры. Контекстные действия с участником и подтверждение цели не должны сдвигать fixed field или перекрывать доступные цели. Новые группы смешанной руки, inspect, вращаемые/исследуемые тайлы описаны в проекте контракта `playroom/core/size-tokens.json:extensibleZones`; это пока не новый API и не реализация правил. Не передавать скрытые лица/URL ради увеличенного просмотра или анимации раскрытия.

## Общие кнопки и короткое название

`manifest.json` поддерживает необязательный `shortName`: непустую строку до 60 UTF-16 единиц. Например, `"name":"Терраформирование Марса","shortName":"Марс"`. Полное имя остаётся именем игры; Web-шапка сначала уменьшает его шрифт до разумного минимума, затем использует короткое имя и, если нужно, многоточие. Проверка поля одинакова в компиляторе и импортере приложения.

Renderer использует `H.button({icon:'play',label:'Играть',variant:'game',attrs:'data-action="roll"'})`: иконка идёт перед подписью. Можно опустить иконку или подпись; для одной иконки задать `ariaLabel`. Варианты: `primary`, `secondary`, `danger`, `plain`, `outline`, `game`; доступны `disabled`, `active`, `type`. Подписи экранируются; `attrs` содержит только доверенные атрибуты разработчика. Генератор и оформление принадлежат `shared/components/game-components.{js,css}`, геометрия задаётся общими токенами приложения. Не создавать отдельную копию стандартной кнопки в паке; карты, кубики и счётчики используют свои канонические компоненты.

Общие типы элементов, принадлежность окантовки типу колоды и независимые рубашки
наборов описаны в [PIECE-TYPES.md](PIECE-TYPES.md).

## Одновременный выбор и квадратные карты

Общие чистые модули `decision-window`, `tactical-grid`, `effect-batch`, `bot-policy` подключаются через `sharedDomain`. Окно публикует только ID, участников, готовность и версии; планы раскрываются по правилам пакета. Batch сохраняет отдельные причины падения и урона: падение имеет приоритет над лечением и определяет награду независимо от порядка регистрации урона. RNG профилей/ошибок отделяется от колоды; одинаковое решение в том же окне не разыгрывается заново.

Боты описывают стратегии в presentation metadata. `auto` и `random` различаются; назначенный профиль сохраняется в Position. Новые параметры и окна необязательны для остальных паков. `cardFrame(...,{shape:'square'})` и `cardBack({shape:'square'})` используют общий card-deck. Высота руки и список игроков принадлежат host, не styles.css пака. `publicFrames` получает только разрешённые кадры; состояние и скрытые планы не зависят от показа фаз.

Mage Brawl основан на prototype `97d984a`, A/v3.0 с уточнениями v3.1: щит внутри цепочки и суммарное лечение/урон одной скорости. Добор выживших следует после явного выбора базы и добора возрождающихся. Сравнение фиксированных состояний хранится в companion `tests/fixtures/mage-brawl-reference.json`; оно не требует одинаковых Python/JS RNG.

`publicFrames` выводит первый публичный кадр сразу в HTML. Кадр может содержать `players` — разметку стандартных `H.playerPanel`, собранную из публичного снимка; `livePlayers` соответствует итоговому `live`. Начальный `playerContent` должен соответствовать первому кадру. `sound`/`pack` задают cue кадра. Контроллер синхронно переключает поле и стандартные панели, а приватная рука недоступна до итогового кадра. Начальный снимок создаётся до расходования карт и ульты, без планов. `PlayroomPublicSequence.defer(host, callback)` откладывает только окно результата, не авторитетные правила.


### Контракт участников сцены

`presentation.scene(projection)` возвращает ровно одного участника на каждый
индекс игрока: `{player, metrics}`. Поле `id` вместо `player` не допускается.
Индексы уникальны, находятся в пределах `projection.playerCount`; порядок массива
не задаёт идентичность. Метрики имеют уникальный в пределах участника `id`,
`kind`, конечное числовое `value` и `label` (MessageRef до локализации).
Для жетонов `display` задаёт `icon`, целую `capacity` от 1 до 64 и необязательный
булевый `overlap`. Значение жетона — неотрицательное безопасное целое;
`capacity` означает минимальное число слотов, поэтому накопленные короны могут
его превышать. SDK проверяет эти поля до перевода и передачи renderer, без
копирования поля и рук. Эти проверки не заменяют фильтрацию приватной проекции.

В API 4 это часть SceneModel вместе с EntityRef, геометрией зон и публичным
PresentationPlan. Поля правил renderer недоступны.

## Правила для новых игроков

Следуйте [структуре и проверке книг правил](PLAYER-RULES.md): цель → подготовка → ход → особые механики → завершение. Один локализованный элемент `rules` содержит заголовок первой строкой и абзацы следующими строками. Пояснения настроек и текущие значения приложение выводит отдельно в конце. Короткая памятка карты не заменяет полные правила. Проверять объяснение эффекта по domain, а не только по старой формулировке.

## Сложность ботов

Новые настройки участника: `botSettings:{strategy,difficulty}`, уровни `easy`, `medium` (по умолчанию), `hard`. Стратегия остаётся независимым выбором, если пак её предоставляет. Пятый аргумент `bot(projection,actor,commands,memory,context)` содержит `difficulty`, `depth`, `errorRate` и воспроизводимый `random()`. Сложность меняет оценку решений и шанс ошибки; сложный бот не безошибочен. Память Пексесо использует вероятности 35/18/6%, без периодической зависимости от номера хода.

Runtime применяет альтернативное решение того же типа; не дублируйте эту вероятность в паке. Для собственной модели ошибки объявите `botHandlesDifficulty:true`. `botMistakes` ограничивает допустимые альтернативы без доступа к закрытому состоянию. Точные контракты — SDK приложения. Для старых runtime используйте значения по умолчанию аргумента context. Автоматические действия человека не должны получать ошибки бота.

Сценарии обучения описываются чистой фабрикой в `presentation/tutorial.js` с внедрённым переводчиком. `view.js` регистрирует её результат после renderer. Модуль включается только в sourceModules.view; он не меняет модель, не обращается к DOM/storage/сети. [Границы приложения](https://github.com/GraphGiraffe/boardgame-playroom/blob/main/docs/DEVELOPER-ARCHITECTURE.md).
