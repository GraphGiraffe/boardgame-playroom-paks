# Создание пака для ХОД 0.17

Коллекция 0.6.1 допускает engineApi 1 и 2, viewApi 2, контейнер 1. Учебный [private-counter](../examples/private-counter/README.md) показывает полный минимальный исходник и приватную цель; это пример, не игра основной коллекции. UNO демонстрирует руки/реакции, шашки — поле и выбор цели, змеи — общий кубик.

## От примера до установки

Из корня этого репозитория при соседнем checkout приложения `../playroom`:

```sh
bash scripts/codex/setup.sh --app-dir ../playroom
python3 build.py --include-examples --output-dir dist/authoring
(cd dist/authoring && sha256sum -c SHA256SUMS)
```

Откройте приложение через `bash scripts/codex/serve.sh` из его каталога. В «Паки игр» установите `dist/authoring/private-counter-0.3.0.playroom-pack.json`, создайте партию и проверьте личный/публичный вид. Этот маршрут использует настоящее приложение; специальный Node preview host не обязателен.

Для своей игры скопируйте каталог examples/private-counter в packs/my-game. Согласованно замените id/name/version в manifest.json, регистрации правил и view, а также корневой CSS-класс. Задайте min/max, пресеты и правила вашей игры. Не меняйте уже опубликованный private-counter под прежним номером. Для своей новой версии используйте новый SemVer.

```sh
python3 build.py --output-dir dist/my-game
```

Сборщик включает каталоги packs, проверяет контракт и создаёт JSON каждой игры. Выберите `my-game-<version>.playroom-pack.json` в менеджере приложения. Не добавляйте игру в исходники ядра или index.html. При полном тесте стандартная коллекция из двенадцати игр должна оставаться доступной.

## Структура и версии

Обязательны manifest.json, rules.js, view.js, styles.css; необязательны sounds.js, assets/ и config/. manifest.js генерируется сборщиком. ID каталога, manifest и двух регистраций совпадают. Контейнер допускает до 128 файлов и 4 MiB; пути локальные без .., абсолютных путей и симлинков. Двоичные файлы включаются в JSON как data URL.

engineApi определяет контракт правил; viewApi=2 — контракт игровых элементов; stateVersion — схему состояния. Номер коллекции не заменяет version игры. Сохранение использует точную пару id/version; изменение правил/view/resources опубликованной игры требует новой версии. Автоматической миграции старого состояния нет.

## Правила и приватность

Регистрируйте один пак через TabletopCore.register. create заполняет state.data; legal перечисляет разрешённые действия; apply изменяет рабочую копию и задаёт следующий ход/исход. reactions разрешает внеочередные реакции, bot/botReaction выбирают из допустимого списка. validateState проверяет восстанавливаемые данные.

Используйте RNG ядра, сериализуемые данные и устойчивые ID компонентов. create учитывает options.resolvedFirstPlayer, если этот режим поддерживается. Не используйте DOM/Date/случайность окружения внутри игровой логики. События и sound-метаданные описывают результат, а не повторно меняют правила.

project(out, viewer, fullState) закрывает ваши нестандартные секреты до view/сети. У зрителя viewer=-1. Полное Session.export нельзя отправлять соперникам. Не раскрывайте руки в логах, HTML, доступных подписях, статусах или animation metadata. Проверьте не только экран, но и полученный JSON.

## Представление и ресурсы

PlayroomViews.register связывает ID с render(projectedState, viewer, actions, ui). Возвращайте api:2, family, playerContent и elements.field/hand/actions/status/auxiliary; дополнительные поля сверяйте с [действующим API](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/GAME-ELEMENTS-API.md).

Расположение игроков, toolbar, рук, счётчиков и общих объектов принадлежит приложению. View выбирает собственную графику и разрешённые действия. H.source/H.target связывают игровой объект с action; H.hand формирует общую руку; H.playerContent — разрешённое содержимое игроков. Не копируйте обработчики scroll/drag из движка. Неходовые карты должны оставаться доступными для прокрутки/осмотра.

Используйте H.esc для текста, H.actionAttr для действий, H.icon для общих значков. Счётчики points/wins/pieces передают публичные числа; pieces рисуется кругом, подпись сохраняется для доступности. Компактная графика не меняет данные и не раскрывает скрытую карту; для неё H.back.

CSS ограничивайте классом своей игры. Общие селекторы сцены/игроков/руки и внешние @import запрещены. PlayroomPack.asset('assets/file.svg') и локальный CSS url(...) разрешают включённые ресурсы. Не рассчитывайте на переписывание произвольных JS-строк с путями; используйте asset(). Файлы/лицензии ресурсов храните внутри пака. Для повторяемых карт, кубика, фишки и корабля используйте исходники `shared/`: укажите `sharedUi: true` и имена SVG в `sharedAssets`, например `card-back.svg` и `die.svg`. Сборщик встроит общий UI-код и эти ресурсы в каждый самостоятельный JSON.

В engineApi 2 вызов `TabletopCore.finish(state, [индексы победителей])` оформляет несколько победителей одной партии; `state.winners` передаётся вместе с обычным `state.winner`. Пример — командное Лудо и Дурак.

## Проверка и публикация

- Сборка и SHA256, JS-синтаксис; установка нового JSON и обработка отсутствующего/битого ресурса.
- Создание/полная партия/боты/Hotseat, легальные и нелегальные ходы, реакции, завершение.
- Сохранение/продолжение/replay без новой раздачи; точная версия и приватность каждого viewer.
- Портрет 320/390 px, короткий landscape, длинные руки, обе оси скролла, touch/drag/swipe и reduced motion. Публичный Стол без приватной руки/управления.
- Сетевой хост и клиент получают одинаковый подтверждённый результат, но разные разрешённые данные. Повтор команды не создаёт второй штраф/ход.

Запустите `bash scripts/codex/check.sh` и совместный `bash scripts/codex/check.sh --full --app-dir ../playroom`. Для новой игры добавляйте содержательные проверки правил/проекций в существующий набор приложения: общий прогон существующих игр не доказывает корректность нового пака.

Публикуйте новый versioned JSON с SHA256 и исходниками; содержимое старой версии неизменно. Документация правил: [PACKS](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/PACKS.md); [формат](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/PACK-FORMAT.md). Пак исполняется с доверием пользователя; sandbox, подписи, расширенный SDK и игровые часы — будущие работы.

## Приёмка интерфейса rc3

Перед копированием сверяйте два подходящих примера: UNO/Спроси рыбу для руки и выбора; Змеи/Лудо для доски и движения. Общая библиотека shared содержит каноническую карту 70×98 (5:7), квадратный кубик и обёртку обложки 300×180. Не переопределяйте ширину и высоту карты независимо: в Пексесо это приводило к почти квадратным картам.

- Рука — H.hand в elements.hand; действия — elements.actions с actionReserve; shared — только общий объект. Появление «Продолжить» не изменяет поле.
- Доска указывает fieldAspect; таблица/адаптивная сетка — fieldSizing: content. Клетки, кубик и круги остаются квадратными/круглыми при любом размере.
- Соперника выбирают его карточкой, карту — самой картой. Используйте targetKind/targetSource/targetChoice по контракту приложения, без матриц кнопок и закрытых ID.
- Счётчики не дублируют handCount. Текущие итоги вычисляют правила и передают в проекцию; view их только показывает.
- Объекты получают устойчивые публичные motion-маркеры; звук задаётся через extra.sound или документированный fallback. Не запускайте собственные таймеры, AudioContext или сетевые загрузки медиа.
- Скриншот без действий, с открытым onboarding или только начальный экран не является проверкой игры. Нужны состояния до/после действия, история, обе ориентации, открытая/закрытая рука и максимальный состав игроков. Проверяйте DOM-проекцию на отсутствие секретов.
- При изменении shared пересоберите каждый использующий пак и увеличьте его версию. SHA старых опубликованных JSON остаются прежними. Пример rc3: семь новых игр 0.1.1 и Дурак 0.4.1 используют sharedUi; Дурак получает обновлённую рубашку с пропорциями 5:7.

Файловый звук UNO хранится в assets/uno-call.wav и встраивается в sounds.js; эти байты должны совпадать. Остальные игровые сигналы используют общую синтезированную библиотеку приложения. Проверять звуки нужно с включённой настройкой после пользовательского жеста; загрузка/повтор snapshot не должны повторно проигрывать событие.

## Новые контракты RC.4 / preview.3

Обязательный источник интерфейсных решений — [RC4-CONTRACTS приложения](https://github.com/GraphGiraffe/boardgame-playroom/blob/dev/docs/RC4-CONTRACTS.md). Не копируйте старые popup-руки, player-name tabs и slogan badges.

- `tags`: 1–3 уникальных разрешённых ID, минимум один type. Копия реестра — `shared/tags.json`, источник приложения — `core/tags.json`. Поддерживаются type и mechanic, состав участников хранится отдельно в `playModes`. Новые ID вводятся одновременно в оба реестра; build/import отклоняют неизвестные. Например Рыба `['cards','combinations']`, Акулина `['cards','combinations','shedding']`. Количество не является тегом.
- `playModes: [{id:'individual',players:[2,3,4],teams:false}]`; teams:true только для реализованного режима. Соло значит один человек без соперника, дуэль строго двое во всём паке, три строго трое. 2+/3+/4+/6+ отражают допустимое число, не минимальный порог правил. Не обещайте состав по наличию ботов.
- `settings[].visibleWhen: {deck:'54'}` скрывает неактуальную опцию в редакторе и описании правил. Правила всегда самостоятельно нормализуют значения; скрытие не является проверкой безопасности. `legacyPresets` позволяет перенести старый preset в раздельные настройки при создании новой партии, не мигрируя сохранённые точные версии.
- `fieldSizing:'scroll'`: ограниченное поле для таблицы с собственным scroll container. Ятзи использует 56px столбцы, sticky подписи/аватары/итог. `H.avatar` переиспользуется в таблицах и кнопках, внутри кнопки 24px. Числа считаются в rules.project, view не меняет состояние.
- `H.indicators` и `playerContent.indicators` дают иконки со значением и доступным label. Для флота `size` — длина корабля (число палуб и труб в силуэте), `value` — число живых кораблей; ноль окрашивается красным. Одинаковый счётчик используется над полем и в карточке игрока. Не дублируйте существующий handCount.
- Закрытую карту выбирают по индексу в текущей руке. Карточка игрока открывает сетку в поле, 5:7, без перекрытия. Рука может прокручиваться вертикально; порядок значим. Акулина вставляет карту в случайный промежуток через E.random, остальные карты не сортируются.
- Публичное событие с `transfer:{player,count,from,fromPlayer?,to?}` сохраняет промежуточное перемещение, отсутствующее в финальных руках. from: stock/hand/table, to: table для сброса пары. Никаких ID закрытых карт. Последовательность событий: передача → пара/комплект. Примеры — Акулина и Рыба.
- `privateTo` принимает индекс игрока или непустой массив уникальных индексов. Событие и `transfer` видят только адресаты; остальные получают `publicText` без `transfer`. Отдельный `publicSound` разрешает нейтральную публичную часть; `sound:null` запрещает fallback. Пара/квартет публичны и получают success. В Акулине адресаты закрытой передачи — вытянувший и владелец руки; карта и её позиция не входят в публичные данные и звук. Ятзи использует success/success.special/success.yatzy только после принятого score; ноль — notify.
- `presentation:{type,cell}` — только открытые сведения для сетевой анимации. `ui.presentationTurn` позволяет завершить показ результата до смены поля. `ui.preferences` и data-view-preference — индивидуальный параметр без изменения комнаты; `viewState` — до смены хода. Не помещайте личный followOpponent в общие settings правил.
- Морской бой: корабли не касаются в обоих вариантах; shots — настоящие выстрелы, marks — автоматическое окружение. announceSinking=off скрывает чужие fleetCounts и sunk; бот принимает решение только по наблюдениям. WAV start/miss/hit/sunk и генератор `scripts/generate_battleship_sounds.py` принадлежат паку; при потоплении звучит только sunk.
- Лудо: diceCount=1/2/3, каждый кубик независимо, used хранится, невозможный сейчас кубик не теряется до исчерпания допустимых ходов набора. sixReroll перебрасывает только шестёрки. guaranteedExit после трёх неудачных наборов у всех оставшихся на базе выводит ровно одну фишку и сразу завершает ход; остальные кубики считаются потраченными. Выход по обычной шестёрке этому ограничению не подчиняется. startPawn — отдельная опция. Команды определяются итоговым порядком мест.
- Дурак: variant simple/throwin/transfer, deck 36/52/54, jokerMode color/universal, endCondition firstout/lastfool. Простой — по пять, подтверждаемый заход 1/3/5, частичный отбой. Перевод до защиты, вместимость нового защитника, исходный атакующий для добора. Конец проверяется после добора. Домашние расширения явно описаны в правилах.

Изменённые состояния получают новый stateVersion: Морской бой/Лудо/Акулина — 2, Дурак — 3. Версии остальных паков также увеличены из-за тегов/метаданных/эффектов. Старые JSON остаются в опубликованных релизах и библиотеке точных версий.


### Лудо 0.1.3: фишка → клетка

Предварительный выбор хранится в `ui.viewState.pawn` и не меняет правила. Только нажатие на клетку отправляет готовое legal action; после перемещения выбор сохраняется до смены хода. Все неиспользованные кубики показывают доступные цели выбранной фишки, одинаковые цели объединяются (меньшее значение кубика, затем меньший индекс). Для гарантированного выхода это сохраняет более крупные кубики. Доступный бросок выделен рамкой; использованные кубики серые.

Начиная с 0.1.4 гарантированный выход завершает ход после перемещения одной фишки. Размеры области действий резервируются до броска: появление подсказок и кнопок не меняет размер поля.

Цели: обычный ход — жёлтый, атака — красный, выход с базы и домашняя дорожка/финиш — зелёные. Промежуточные клетки содержат только точки маршрута. Специального перепрыгивания в правилах нет, синяя цель не используется. Цвет дублируется доступной подписью цели. Фишки соперников не перехватывают нажатие на клетку атаки; локальный выбор не попадает в публичную сцену. Состояние правил и stateVersion=2 сохранены, опубликованный пак 0.1.2 остаётся неизменным.

Игровые цвета доски, фишек и шашек не передавайте через `playerContent.color`: аватары во всех играх используют общую светлую палитру. Ятзи позволяет менять удержание каждого кубика после первого и второго броска, включая освобождение ранее удержанного перед третьим; область управления остаётся одной высоты при всех бросках. Поле Морского боя после переключения должно оставаться по центру и целиком помещаться в выделенную область, включая счётчики.

### Изменения коллекции 0.5.3

`event.speech` — публичная краткая реплика с `speaker`, необязательным `target`, текстом либо иконкой `cards`/`cross`, счётчиком и результатом `success`/`error`. Она показывает бабл у игрока и синюю подсветку адресата. Секретные карты и приватные ответы в реплику не включайте. Чат пользователей хранится отдельно от событий правил.

Морской бой 0.1.4 (stateVersion 3): готовность фиксируется после полной ручной или автоматической расстановки; `ready` хранится в состоянии, старый формат остаётся в прежнем паке.

### Изменения коллекции 0.5.2

Лудо 0.1.6: синий и жёлтый игроки используют фишки и секторы своих цветов; правила и stateVersion не менялись. Прежняя версия пака остаётся доступной для старых сохранений.

Пексесо 0.1.4: несовпавшие карты видны в анимации завершения хода, но закрыты при просмотре следующего хода и истории. Правила действий и stateVersion не менялись.

### Изменения коллекции 0.5.1

Лудо 0.1.5: внешний старт отмечен стрелкой, вход в дом находится перед ним; звёзды на основном пути безопасны. Выход с базы — одно нажатие на доступную фишку, занятая стартовая клетка выполняет выбранный выход.

Акулина 0.1.4 (stateVersion 3): обмен публично показывает только отправителя, получателя и одну закрытую карту. Значение карты не входит в событие или transfer. `outOrder` фиксирует порядок выхода, очки N−1…1 начисляются по мере выхода, последнему 0.

Пексесо 0.1.3 (stateVersion 2): несовпавшая пара остаётся открытой до первого выбора следующего игрока; отдельной команды продолжения нет. Бот помнит открытые карты, но иногда выбирает исследование вместо известной пары.

Ятзи 0.1.4: всем строкам таблицы заранее отведена высота для кнопок записи результата; область таблицы и её прокрутка сохраняются при удержании кубиков в приложении 0.16.1.
