# Подготовка будущих игр и скинов

Статус: **спецификация, без реализации и регистрации**. Новые игры, изображения, кнопка onboarding и варианты оформления не входят в runtime 0.18. Нынешние правила и выбранные скины сохранены.

## Точки расширения игр

Новые `packs/spider`, `packs/klondike`, `packs/thousand` — предлагаемые ID, проверить отсутствие коллизий перед созданием. Каждый получит собственный manifest, domain, presentation, locales/ru, view/styles и semantic events. Правила через GameModel API 3, renderer UI 2, common Source/Target/Hand/Board/Reveal/History; не добавлять switch по game ID в приложение.

Общая standard-deck.create поддерживает 36/52/54, масти ♠/♥/♦/♣, ранги 2–14 и joker-red/joker-black. **32-карточную и двойную колоду нельзя считать уже поддержанными.** Для Тысячи подготовить явную domain-конструкцию 24 карт и согласовать правила; для Паука — состав нескольких колод с уникальными instance ID, отдельными от face ID. Не использовать art ID как игровой ID. Перед реализацией проверить single-player catalogue/lobby/result, stock/waste/tableau/foundation, повторяемость RNG, допустимость отмены и приватность.

Паук/Косынка требуют точного согласования вариантов (масти, раздача, добор, ограничения); Тысяча — торги/прикуп/марьяжи/бочка/штрафы и число игроков. Эти правила сейчас не зафиксированы догадками.

## Скины обычных карт

Два будущих набора: **Русские**, **Атласные**. Каждый содержит 52 лица и **два различимых цветных джокера**, собственную рубашку, main/compact представления. Semantic joker-red/joker-black остаются идентификаторами правил; арт обоих может быть цветным. Выбор в общем меню тем/скинов, не в настройках правил каждой игры.

Референсы скопированы в docs/design/future-skins коллекции. Их роль — узнаваемые мотивы/силуэты/композиция; финальные изображения будут самостоятельными, с меньшим числом деталей и в общем минималистичном стиле. В runtime эти файлы не включены.

## Персонажи и UNO

- Существующий подробный набор сохранить; будущие названия вариантов «Подробный»/«Минималистичный».
- Минималистичные персонажи — новый asset pack с зависимостью/сопоставлением semantic characters, а не замена исходных файлов. Те же фигуры и цветовые роли; выбор скина в аватарах и колоде.
- Оба варианта персонажей используют общие минималистичные рубашки. Разнообразие и случайный выбор в Пексесо остаются domain-механикой, не зависят от скина.
- UNO получает собственную минималистичную рубашку по мотивам рефа 3. Она не меняет face/action IDs и правила игры.

## Контракт подключения оформления

Сейчас AssetResolver принимает family/variant/materials и умеет fallback, AppearanceService хранит локальные skins. Для будущего связанного набора faces+back+avatar сначала определить декларативное соответствие и версию asset manifest. Это **не существующее дополнительное API**. Запрещено определять новый протокол как уже работающий без кода/проверок. Точные dependency versions, digest, offline bundling, main/compact parity и сохранность старых skin IDs обязательны.

Onboarding: открыть общую страницу/окно тем с return destination; имя/аватар остаются draft. Закрытие возвращает тот же draft, Save профиля единственный commit. Отмена/навигация не создают профиль. Эту кнопку реализовать вместе со скинами отдельным патчем.

## Приёмка патчей

Каждый новый skin: все 54 лица различимы, hidden не раскрывает лицо, углы/ранг читаются в overlap, 10 имеет общий шаг, alpha без подложек, одинаковые avatar proportions, цветовые темы/scale50–150/portrait/landscape, offline и неизвестный variant fallback. Все оригиналы/варианты сохранять отдельно от оптимизированного runtime. Каждая игра: pure rules, legal targets, result/timeline, restore/replay, бот/приватность по возможностям, fixed layout до/после действий. Публикация игры/ассетов не требует перепубликации оболочки, пока её контракт не меняется.
