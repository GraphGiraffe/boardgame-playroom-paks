# Разработка

`main` — стабильная линия, `dev` — интеграция. Задача: ветка от dev → Draft PR → готовые проверки → squash в dev. Выпуск: отдельный PR dev → main **merge-коммитом**, затем fast-forward dev, без force-push. Не работать над обычной функцией прямо в main.

Проверьте root, status и текущую ветку; не перезаписывайте чужую работу. Каждый опубликованный packVersion/tag неизменен. Версии приложения, коллекции, отдельных игр и ассетов независимы. Новый API/сохранение требуют явного контракта перехода. Действующие контракты: engineApi 4 / viewApi 3.

Проверки выбираются по фактическому риску, явным списком blocks/case; source checks=none допустим только осознанно, с объяснением. SHA256 и архивы проверяются всегда. Сквозные изменения правил/хранения/сети проверяются совместно с точной companion версией. Push/Ready не запускают Actions автоматически; необходимые ручные проверки выполняются на окончательном SHA.

Публикацию подтверждают успешный deployment сайта и сверка опубликованной оболочки/каталога по SHA256. GitHub Releases в репозиториях приложения и паков не используются. Версии кода и игр сохраняются; старые файлы паков остаются на сайте. Локальные тестовые сборки не являются деплоем.

Сборки, dist, node_modules, временные данные, приватные архивы и соседние проекты не коммитятся. История прежних этапов хранится в Git/CHANGELOG; текущие инструкции описывают действующую версию.

## Локальная сборка и проверка

```sh
bash scripts/codex/setup.sh
python3 build.py --output-dir dist/local
bash scripts/codex/check.sh
```

Это проверка синтаксиса и упаковки; игровые правила и интерфейс проверяются адресно в совместимой копии приложения. `dist/` не коммитится.
