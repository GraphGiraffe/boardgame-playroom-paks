# Разработка и выпуск

`main` — стабильная линия, `dev` — интеграция. Задача: ветка от dev → Draft PR → готовые проверки → squash в dev. Выпуск: отдельный PR dev → main **merge-коммитом**, затем fast-forward dev, без force-push. Не работать над обычной функцией прямо в main.

Проверьте root, status и текущую ветку; не перезаписывайте чужую работу. Каждый опубликованный packVersion/tag неизменен. Версии приложения, коллекции, отдельных игр и ассетов независимы. Новый API/сохранение требуют явного контракта перехода; 0.18 не содержит legacy engine API 1/2.

Проверки выбираются по фактическому риску, явным списком blocks/case; source checks=none допустим только осознанно, с объяснением. SHA256 и архивы проверяются всегда. Сквозные изменения правил/хранения/сети проверяются совместно с точной companion версией. Push/Ready не запускают Actions автоматически; необходимые ручные проверки выполняются на окончательном SHA.

Релиз подтверждают GitHub tag/assets, скачанные контрольные суммы и опубликованный runtime/catalog. Зелёный локальный тест не доказывает deploy. Сначала публичные immutable assets, затем существующая защищённая инфраструктура; private wrapper/секреты не входят в source/release ZIP.

После успешной публикации разрешённая очистка удаляет только доказанно завершённые ветки/заменённые PR. Перед удалением сохранить bundle --all и проверить exact head. main/dev/tags/активные worktrees/уникальная работа сохраняются. Не force-reset dev после squash; stable merge сохраняет общую историю.

Сборки, dist, node_modules, временные данные, приватные архивы и соседние проекты не коммитятся. История прежних этапов хранится в Git/CHANGELOG; текущие инструкции описывают действующую версию.
